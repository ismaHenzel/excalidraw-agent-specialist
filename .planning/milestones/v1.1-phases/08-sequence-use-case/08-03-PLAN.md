<objective>
Author the `diagram-types/use-case.md` TYPE-layer recipe (UML-03) and produce the canonical
use-case example pair, passing the full validate→render→verify loop. Use-case is the
most-native-friendly UML type in this environment: it introduces NO new primitive and composes
entirely from already-shipped elements — native `ellipse` ovals, the committed actor=labelled-box
convention, the existing `group-container` system boundary, and legal association/include
encodings. This mirrors Phase 5's `activity.md` (a pure-composition type) structurally.

Per UML-03: authoring a use-case request (actors via the committed convention, use-case ovals,
system boundary via group-container) must yield a rendered PNG that passes the full loop.

Subject (RESEARCH Open Question 3): an e-commerce Checkout System — 2 actors (Customer, Admin),
5 use-case ovals (Browse Products, Add to Cart, Place Order, Process Payment, View Reports), 1
`«include»` (Place Order includes Process Payment), 1 system-boundary group-container.

Purpose: Use-case has essentially zero hard geometry work — the investment is correctly applying
locked conventions (actor=labelled-box, include=dashed arrow+label) and composing existing
primitives by reference.

Output:
- `diagram-types/use-case.md` — new TYPE recipe (pure composition)
- `examples_excalidraw/use_case_checkout.excalidraw` + `examples/use_case_checkout.png` —
  canonical pair passing the full loop (EX-01/EX-03 exit criteria for the use-case type)

primitive. Both run in Wave 2 after 08-01. Resolver row wiring is deferred to `08-04-PLAN.md`
(EX-03 gate). This plan does NOT touch `diagram-types/README.md`.
