# Requirements Archive: v1.1 — Diagram Families & UML Expansion

**Archived:** 2026-06-09
**Original definition:** 2026-06-03
**Core Value:** The agent draws recognizable, real-world diagram families (tech architecture, data models, UML) correctly — guided by a per-diagram-type knowledge layer — while preserving the self-verifying render→verify→fix loop shipped in v1.0.

> All 21 v1.1 requirements shipped. See traceability table below for per-requirement outcomes.

## v1.1 Requirements (All Complete)

### Taxonomy & Picker (TAX)

- [x] **TAX-01**: The `/excalidraw` command's intent step presents four diagram **families** — Tech Architecture, Data Modeling, UML / SW-Engineering, Flow / Process — as the top-level choice
- [x] **TAX-02**: When the chosen family has more than one type, the command asks a second **type** sub-pick; two-tier flow respects `AskUserQuestion`'s 4-option cap with documented plain-text numbered-menu fallback
- [x] **TAX-03**: The resolved family+type drives dispatch via a single authoritative resolver table in `diagram-types/README.md`

### Diagram-Type KB Layer (DTKB)

- [x] **DTKB-01**: `diagram-types/` KB layer exists with `README.md` resolver table (type → recipe · sub-patterns · example PNG)
- [x] **DTKB-02**: Each type file states purpose, how to draw it, and composed sub-patterns — referencing `kb/` primitives
- [x] **DTKB-03**: Two KB layers cross-reference each other; `kb/README.md` documents the two-layer relationship
- [x] **DTKB-04**: Notation workarounds committed once in `notation-conventions.md` (crow's-foot, aggregation/composition diamonds, generalization triangles, actor convention)

### Specialist & Loop Integration (INT)

- [x] **INT-01**: `excalidraw_specialist.md` reads the `diagram-types/<type>.md` recipe first given a resolved family+type; loop, validator, and verifier behavior unchanged
- [x] **INT-02**: Compartmented-box construction documented in `compartmented-box.md`; multi-line single `text` blocks explicitly disallowed

### Data Modeling Types (DM)
