<objective>
Build the shared sequence-diagram geometry primitive `kb/lifeline-activation.md` ONCE (per
UML-01 Success Criterion 1), and resolve the center-x verifier-check decision (RESEARCH.md
Open Question 1) before any sequence example is authored. This is the Wave-1 foundation that
`08-02-PLAN.md` (sequence.md) `@`-references — the exact structural analog of Phase 7's
`kb/relationship-endpoint.md` primitive built first in `07-01-PLAN.md`.

Per UML-01: the sequence type needs lifelines, activation bars, ordered solid messages, and
dashed returns, with each activation bar centered on its lifeline x and message Y values
increasing top-to-bottom. All of that geometry is pinned here so the first render is close and
the 3-iteration loop is only for polish.

Purpose: Geometry lives ONLY in the PRIMITIVE layer (two-layer KB rule). Front-loading the
deferred lifeline/activation pixel values (PITFALLS.md Pitfall 4, SUMMARY.md research flag)
into one file means `sequence.md` composes by reference and never re-derives coordinate math.

Output:
- `kb/lifeline-activation.md` — new primitive (geometry + JSON skeletons + hard-rule notes)
- A recorded decision on the center-x structural check (and, if adopted, the check itself in
  `verifier_structural.py`)
</objective>
