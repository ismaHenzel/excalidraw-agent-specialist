IMAGE-PATH RESOLUTION ORDER (verbatim port of scripts/render_excalidraw.py:69-94 — RESEARCH.md "Don't Hand-Roll"):
  1. If file_path is absolute, use as-is.
  2. Otherwise, resolve against the .excalidraw file's parent directory.
  3. If still not found AND $EXCALIDRAW_ASSETS_DIR is set, resolve against that.
  4. If still not found, emit `image_path_unresolvable` issue.
  RATIONALE: the verifier MUST match the renderer's resolution — flagging paths the renderer would load (or vice versa) breaks the consumer's trust in the report.

ARROW ENDPOINT MATH (RESEARCH.md §Common Pitfalls #1, #2):
  - arrow.points[0] is ALWAYS [0, 0] (element-local coordinates).
  - Last-point absolute = (arrow.x + points[-1][0], arrow.y + points[-1][1]).
  - Architect's Precision diagrams use axis-aligned elbows; assume angle == 0 (rotation transform NOT needed for v1).
  - "On border within tolerance" for rectangle = point is inside the bbox expanded by 8 px AND outside the bbox shrunk by 8 px.
  - For ellipse with bbox (x, y, w, h): center (cx, cy) = (x+w/2, y+h/2); semi-axes (a, b) = (w/2, h/2).
    Normalized distance d = sqrt(((px-cx)/a)^2 + ((py-cy)/b)^2). On border if |d - 1| * min(a, b) <= 8.
  - For diamond with bbox (x, y, w, h): 4 segments connecting bbox edge midpoints. On border if min(distance to each segment) <= 8.

TEXT-OVERFLOW CONTAINING-SHAPE LOOKUP (RESEARCH.md §Common Pitfalls #3):
  - Containing shape = SMALLEST rectangle/ellipse/diamond whose bbox encloses the text bbox.
  - Skip the check entirely if the text element has a non-null `containerId` (Excalidraw auto-wraps in that case — RESEARCH.md Open Question #4).
  - Text estimated width = len(text) * MONOSPACE_ADVANCE_RATIO * fontSize (use fontSize=20 default if missing).
  - Text estimated height = fontSize (approximate; rough single-line model is acceptable for v1).
