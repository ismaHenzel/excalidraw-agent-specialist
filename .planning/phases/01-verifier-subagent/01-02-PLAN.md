<objective>
Author the standalone `excalidraw_verifier.md` Claude Code subagent that runs structural + visual verification on a single `.excalidraw` file and emits a structured pass/fail report.

This subagent is the orchestrator: it gates input, shells out to `scripts/verifier_structural.py` (Plan 01) for deterministic structural checks, multimodally `Read`s the rendered PNG to apply 5 visual checks, merges both halves into a single report, writes it to a sibling JSON file, and echoes the same JSON in a fenced block as the last segment of its final assistant message.

Purpose: separating the verifier from the main `excalidraw_specialist` produces fresh-eyes review (Pre-roadmap key decision) and provides Phase 2's auto-fix loop with a stable file contract (`<basename>.verifier-report.json`) to consume without parsing LLM messages.

Output: one new file at `.claude/agents/excalidraw/excalidraw_verifier.md`. Format mirrors `excalidraw_specialist.md` exactly — YAML frontmatter + XML-style body sections — but with verifier-appropriate section names and a strictly limited `tools:` allowlist (no MCP, no Edit, no Task).

This plan does NOT touch the existing `excalidraw_specialist.md` (locked by Phase 1 scope per CONTEXT.md `<domain>` "OUT OF SCOPE: ... NOTHING wires the verifier into the main specialist in this phase").
</objective>

YAML FRONTMATTER (CONTEXT.md D-12; mirror excalidraw_specialist.md:1-5 syntax):

  name: excalidraw_verifier
  description: <when-to-delegate, one line, see RESEARCH.md §Code Examples for verified draft>
  tools: Read, Glob, Grep, Bash, Write
  ---

  Rules:
  - `tools:` is allowlist semantics — the subagent can ONLY use the 5 listed tools.
  - NO `mcp__*` tools (D-12 explicitly excludes MCP).
  - NO `Edit` or `Task` tools.
  - The `tools:` line must end with `Write` (or contain it anywhere) — the canonical report file is emitted via Write.
  - `model:` is omitted (defaults to `inherit` — RESEARCH.md Open Question #1 recommends this for vision quality).

SPAWN CONTRACT (CONTEXT.md D-13):
  Input: exactly ONE argument — an absolute path to a `.excalidraw` file.
  Derived: `<basename>.png` (replace `.excalidraw` suffix with `.png`).
  Error path: if either file is missing, emit the `verifier_internal_error` report immediately (do NOT silently proceed).

ISSUE SCHEMA (CONTEXT.md D-03 — exactly 5 keys per issue):
  {
    "check":         "<documented check name>",
    "element_id":    "<Excalidraw element id, 'unknown', or '—' for verifier_internal_error>",
    "severity":      "error" | "warning",
    "detail":        "<short human-readable description>",
    "suggested_fix": "<imperative verb-first free text; references element_id when relevant>"
  }

REPORT SCHEMA (CONTEXT.md D-01..D-03):
  {
    "passed":     <true iff issues is empty OR every issue has severity == "warning">,
    "checked_at": "<UTC ISO 8601 timestamp like 2026-05-21T12:34:56Z>",
    "source":     "<absolute path to the .excalidraw file>",
    "png":        "<absolute path to the derived PNG>",
    "issues":     [<zero or more issue objects>]
  }

REPORT TRANSPORT (CONTEXT.md D-01, D-02 — DUAL CHANNEL):
  Channel A (canonical, machine-readable): the same report object written via the Write tool to `<basename>.verifier-report.json`, sibling to the .excalidraw file. Overwritten on every run; no version suffix per LOOP-03.
  Channel B (human-debugging redundancy): the same report object echoed in a fenced ```json block as the LAST segment of the final assistant message — nothing after it, no trailing prose.
  Both channels MUST be byte-identical — produced by ONE `json.dumps` invocation, captured into a variable, written to both destinations.

DOCUMENTED CHECK NAMES (CONTEXT.md D-04, D-05, D-08; subagent body must reference all visual ones explicitly):
  Structural (delegated to Plan 01's helper — subagent reads them from helper stdout):
    error:   arrow_endpoint_unanchored, text_overflow_static, image_path_unresolvable, raw_emoji_in_text
    warning: roughness_nonzero, fontfamily_nonmonospace, arrow_points_too_few, arrow_missing_elbow_roundness
  Visual (LLM-side, applied by the subagent against the rendered PNG):
    error: text_overflow_visual, arrow_disconnected_visual, icon_blank, missing_glyph_box, layout_collision

VISUAL-CHECK SEMANTICS (CONTEXT.md D-07, D-08, D-09):
  - PER-DIAGRAM ABSOLUTE JUDGMENT ONLY. NO pixel-diff vs examples/*.png. NO cross-reference to canonical example renders.
  - text_overflow_visual: text element visibly extends beyond its container box in the rendered image.
  - arrow_disconnected_visual: arrow head or tail visibly does not touch its claimed anchor element.
  - icon_blank: image element rendered as a blank/transparent rectangle (failed to embed).
  - missing_glyph_box: text element renders as one or more tofu boxes (□) instead of real glyphs.
  - layout_collision: two elements visibly overlap when they should not (text-on-text, box-on-box, etc.).
  - All visual checks are `severity: "error"` (D-09). Their `suggested_fix` strings reference JSON ids (not pixel coordinates) — e.g., "Replace text element id: label_3 with an image element pointing to .claude/agents/excalidraw/icons/check.png."

OPERATIONAL SEQUENCE (RESEARCH.md §Pattern 2 — 7 numbered steps, verbatim):
  1. Validate input. Confirm one absolute-path argument. Derive `<basename>.png`. If either file missing, emit verifier_internal_error report (both channels) and STOP.
  2. Run structural helper. Bash: `python3 .claude/agents/excalidraw/scripts/verifier_structural.py "$ARG"`. Capture stdout. Parse as JSON array (helper always exits 0 per D-14; if it ever exits non-zero, emit a verifier_internal_error issue capturing the failure).
  3. Read PNG (multimodal). Use the `Read` tool on the derived PNG path. This puts the image into the model's context (multimodal capability inherited from the parent model — confirmed by excalidraw_specialist.md:144 precedent).
  4. Apply the 5 visual checks. Use the in-body visual-check rubric. Produce a JSON array of issue objects mirroring the structural schema.
  5. Merge. Concatenate structural-issues + visual-issues. Compute `passed = all(issue.severity == "warning" for issue in issues) if issues else True`.
  6. Emit canonical file. Build report object (passed, checked_at, source, png, issues). Serialize ONCE via json.dumps with indent=2. Use the `Write` tool to write to `<basename>.verifier-report.json`.
  7. Echo in message. The final assistant message ENDS with a fenced ```json block containing the byte-identical serialization. No prose after the block.

ALWAYS-EMIT-REPORT INVARIANT (RESEARCH.md §Common Pitfall #5, CONTEXT.md "Claude's Discretion"):
  The subagent MUST NEVER terminate without writing the sibling .verifier-report.json file AND echoing the fenced block. Every failure path — missing input, helper crash, malformed PNG, Write permission error — emits a report with at least one `verifier_internal_error` issue:
    {
      "check": "verifier_internal_error",
      "element_id": "—",
      "severity": "error",
      "detail": "<what went wrong>",
      "suggested_fix": "Investigate; this is a verifier bug, not a diagram bug."
    }

PYTHON-VS-PYTHON3 (CONCERNS.md #7, RESEARCH.md Pitfall #6):
  Use `python3` in the Bash invocation, NOT bare `python`. The repo's `validate_and_render.sh:14` uses bare `python` and CONCERNS.md flags this — do NOT propagate the bug.

REPORT-PATH DERIVATION (CONTEXT.md D-01, D-13):
  `<basename>.verifier-report.json` where `<basename>` is the .excalidraw path with the `.excalidraw` suffix replaced. Examples:
    /tmp/foo.excalidraw          -> /tmp/foo.verifier-report.json
    /a/b/c/d.excalidraw          -> /a/b/c/d.verifier-report.json
  The subagent derives the path; the caller does NOT pass it.

OUT OF SCOPE FOR THIS PHASE (CONTEXT.md `<domain>`):
  - Auto-fix loop. The subagent reports; it does NOT mutate the .excalidraw.
  - Pixel-diff against examples/*.png. The visual check is absolute, not comparative (D-07).
  - Modifying excalidraw_specialist.md. That is Phase 2.
  - Always-render mandate at the specialist level. That is Phase 2.
