<objective>
Surgically revise `excalidraw_specialist.md` to enforce a closed-loop "render → verify → fix → re-render → re-verify (×3 cap)" delivery flow on every diagram authoring turn. The edit adds two new XML-tagged body sections (`<content_policy>`, `<verification_loop>`), updates two existing operational mandates (#5 and #7), and preserves everything else verbatim.

The end-state file:

1. Forbids any delivery path that skips `bash scripts/validate_and_render.sh "<path>"` (LOOP-01).
2. Forbids raw Unicode emoji codepoints in `text` elements at generation time, mapping common emoji requests to `image` elements pointing at `icons/{success,failure}_icon.png` (CONT-01 generation half).
3. Mandates delegating to the `excalidraw_verifier` subagent after every render, parsing the sibling `<basename>.verifier-report.json` file via `Read`, and branching on `passed` (LOOP-01 + LOOP-02).
4. Caps the verify cycle at **3 total attempts** (initial verify + up to 2 fix-and-reverify cycles) and emits a grep-friendly honest-failure message on the 3rd consecutive `passed: false` containing labelled paths to the failed PNG, source `.excalidraw`, and verifier report, plus a verbatim issue list (LOOP-02).
5. Maintains sibling-only artefact discipline: after any iteration the only files alongside `<basename>.excalidraw` are `<basename>.png` and `<basename>.verifier-report.json`, with no `.v1`, `_iter1`, or `.bak` siblings ever (LOOP-03).

This phase ships a single edited file — no new scripts, no new fixtures. Phase 3 will validate the closed loop end-to-end on representative defect diagrams.
</objective>

     - A fix is a mutation to the source `.excalidraw` JSON only.
     - The specialist uses `Bash` to apply the mutation (the exact technique — `python3 -c`, heredoc, etc. — is the specialist's choice).
     - The specialist NEVER asks the verifier to perform the fix (the verifier is read-only by Phase 1 contract).

         Failed PNG: <absolute path>
         Source:     <absolute path>
